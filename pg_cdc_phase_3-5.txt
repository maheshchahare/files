# 2. ABSOLUTE SAFETY INVARIANT

The following invariant remains mandatory:

> If `app_confirmed_lsn = X`, X must be a verified COMMIT-row LSN, and the complete transaction represented by X and all preceding transactions covered by that watermark must already have been durably applied to Delta.

Therefore:

### Forbidden

Never allow:

```
persist(app_confirmed_lsn = X)
```

before:

```
all Delta effects represented by X are durably applied.
```

Never advance the slot before the corresponding durable application state has been persisted.

Never use:

```
raw_rows[-1]
```

as the watermark.

The selected watermark MUST come from a verified `C` row.

# 7. CRASH E1

## Crash immediately after PEEK, before APPLY

Sequence:

```
PEEK
↓
CRASH
↓
PROCESS RESTART
↓
PEEK AGAIN
↓
APPLY
↓
PERSIST
↓
ADVANCE
```

Expected behavior:

* No application watermark may advance because APPLY never completed.
* `confirmed_flush_lsn` must not incorrectly move because the slot was only peeked.
* On restart, the same WAL transaction(s) must remain available.
* The transaction must be applied successfully.
* Final Delta state must equal PostgreSQL.
* Slot advancement must occur only after durable persistence.
* No source transaction may be lost.

Explicitly verify:

```
app_confirmed_lsn_before_crash
==
app_confirmed_lsn_after_restart_before_apply
```

and that the transaction is still present in the slot.

# 9. CRASH E3

## Crash after durable persistence but before slot ADVANCE

This is the most important watermark-ordering test.

Sequence:

```
PEEK
↓
APPLY
↓
PERSIST app_confirmed_lsn = X
↓
CRASH
↓
PROCESS RESTART
↓

↓

↓

↓
ADVANCE
↓

```

Expected behavior:

* Durable `app_confirmed_lsn = X` exists.
* X must be a verified COMMIT LSN.
* Delta already contains all effects through X.
* New slot has NOT yet been advanced.
* Restart must not interpret the situation as WAL loss.
* Replay of X must be safe.
* The slot may then be advanced to X.
* No transaction may be skipped.
* No duplicate logical data may remain.
* Final PostgreSQL and Delta states must match.

Pay special attention to the existing startup rule:

```
confirmed_flush_lsn < app_confirmed_lsn
    => NORMAL / safe replay
```

If this is the exact intended state, prove that the new-generation recovery path handles it correctly.

Do not introduce a new recovery semantic unless absolutely necessary.
