# Claude Code — Phase 3 Stage 5

## Real New-Generation CDC Integration & End-to-End Selective Recovery

We are continuing the PostgreSQL → Databricks CDC project.

Phase 3 Stage 4 implemented the selective-recovery orchestration skeleton and validated:

* new slot creation is structurally first;
* new-slot creation is idempotent;
* old-slot analysis is non-destructive;
* affected-table manifest persistence is idempotent;
* selective reload routing works;
* old-slot retirement is gated;
* retirement is idempotent;
* DDL protection is a conservative policy guard;
* existing 76/76 tests pass.

However, Stage 4 explicitly identified two remaining implementation gaps:

1. `run_selective_recovery()` does NOT yet execute a real new-generation CDC cycle. Steps 5–7 are currently state-transition placeholders.
2. The selective-recovery path is NOT yet wired into the live `recovery_required` branch.

This stage must close those gaps.

The production feature flag MUST remain disabled by default.

Do not touch the production slot during testing.

---

# 1. AUTHORITATIVE RECOVERY ORDER

The following sequence is mandatory:

```text
CREATE NEW SLOT
      ↓
ANALYZE OLD SLOT
      ↓
PERSIST AFFECTED-TABLE MANIFEST
      ↓
SELECTIVELY FULL LOAD MANIFEST TABLES
      ↓
PEEK NEW SLOT
      ↓
APPLY NEW SLOT CHANGES
      ↓
PERSIST CHECKPOINT / app_confirmed_lsn
      ↓
ADVANCE NEW SLOT
      ↓
VALIDATE SUCCESSFUL INCREMENTAL CYCLE
      ↓
RECOVERY COMPLETE
      ↓
RETIRE OLD SLOT
```

Do not change this ordering.

In particular:

```text
OLD SLOT ANALYSIS → NEW SLOT CREATION
```

is forbidden.

And:

```text
FULL LOAD → NEW SLOT CREATION
```

is forbidden.

The new slot must exist before old-slot analysis and before any selective full load.

# 3. CRITICAL SAFETY INVARIANT

Preserve the existing Phase 1 invariant:

> `app_confirmed_lsn = X` means X is a COMMIT (`C`) row LSN and every transaction through X has been durably applied to Delta.

Therefore:

```text
PEEK
  ↓
APPLY
  ↓
last COMMIT LSN
  ↓
persist state/checkpoint
  ↓
ADVANCE
```

Never:

```text
ADVANCE
  ↓
APPLY
```

Never advance the new slot before durable application.

Never set `app_confirmed_lsn` to:

* BEGIN LSN
* INSERT/UPDATE/DELETE LSN
* arbitrary WAL LSN
* last array element without verifying C

# 4. REAL NEW-GENERATION CDC CYCLE

Replace the current placeholder:

```text

        ↓
RECOVERY_COMPLETE
```

with an actual incremental CDC execution cycle using the existing production machinery.

Conceptually:

```text

```

Do not duplicate the normal CDC implementation.

If the existing functions cannot be cleanly parameterized for the new slot/generation, refactor minimally and preserve existing behavior.

# 12. CRASH TEST E — DURING NEW CDC

This is the most important missing test.

Force a crash at multiple points:

### E1

After new-slot PEEK but before Delta APPLY.

Expected:

* `app_confirmed_lsn` does not advance;
* retry can safely replay the transaction.

### E2

After Delta APPLY but before checkpoint/state persistence.

Expected:

* retry is idempotent;
* Delta MERGE does not corrupt data;
* checkpoint still represents the last durably confirmed LSN.

### E3

After checkpoint/state persistence but before slot ADVANCE.

Expected:

* restart may replay the already-applied transaction;
* Delta MERGE remains idempotent;
* no data loss;
* eventual state converges.

### E4

After slot ADVANCE.

Expected:

* durable `app_confirmed_lsn` is already at the corresponding COMMIT LSN;
* no committed transaction is lost.

Do not simply mock these failures.

Use real disposable slots and the actual CDC functions.

# 18. SELECTIVE RECOVERY FAILURE FALLBACK

Define what happens when selective recovery starts but cannot safely complete.

Examples:

* new slot creation failure;
* old slot disappears;
* WAL gap;
* manifest persistence failure;
* DDL policy rejects selective recovery;
* selective full load fails;
* new CDC fails;
* checkpoint inconsistency;
* generation mismatch.

The system must NOT silently continue as NORMAL.

Determine the safest fallback.

Important:

If the new slot exists and selective recovery fails, do NOT automatically drop it unless the state machine explicitly proves that doing so is safe.

Similarly, do not drop the old slot merely because selective recovery failed.

Recovery must fail closed.

# 19. DDL POLICY

Keep the Stage 4 conservative DDL policy.

Do NOT claim that PostgreSQL table metadata provides exact historical DDL detection.

The current rule should remain:

```text
DDL status unknown
        ↓
selective recovery prohibited
        ↓
```


Do not weaken the policy merely to make tests pass.

# 29. ABSOLUTE SAFETY INVARIANT

The implementation must never allow a committed source transaction to exist in neither:

```text
old-slot recovery analysis
```

nor:

```text
new-slot CDC
```

The authoritative partition is:

```text
                 NEW SLOT CREATED
                       │
          ┌────────────┴────────────┐
          │                         │
       BEFORE                     AFTER
          │                         │
   OLD SLOT WAL              NEW SLOT WAL
      ANALYSIS                    CDC
          │                         │
 affected tables                    │
          │                         │
 selective full load                │
          └────────────┬────────────┘
                       │
                  final state
                       │
                       ▼
               validation
                       │
                       ▼
             retire old slot
```

Do not compromise this invariant.

If any implementation detail conflicts with this invariant, stop and report the conflict rather than weakening the invariant.
